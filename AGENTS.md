# Совместная работа Codex и Claude

Эти инструкции общие для обоих агентов. Прочитать также `CLAUDE.md`: там предметные ограничения, карта файлов и команды сборки. Разделение веток и порядок интеграции определяются здесь; явные указания пользователя имеют приоритет.

## Ветки и рабочие каталоги

- Общая ветка проекта: `claude/alchemy-talis-crash-test-6g8sk7`. Claude ведёт эту ветку и объединяет готовые изменения Codex.
- Codex работает в отдельной ветке `codex/<задача>` и отправляет коммиты только в неё. Не пушить в общую ветку или ветки Claude; исключение — явное поручение пользователя интегрировать изменения.
- Для каждой новой задачи Codex: проверить `git status --short`, выполнить `git fetch origin`, создать новую ветку от `origin/claude/alchemy-talis-crash-test-6g8sk7`. Если среда выдала ветку `work`, это техническое имя, а не основание пушить в общую ветку.
- Не переключать ветку поверх незавершённых изменений. Сохранить существующую работу и выяснить принадлежность изменений перед операциями, которые её затрагивают.
- Каждый агент использует свой checkout в своей среде. Не запускать двух агентов в одном рабочем каталоге: ветка и файлы там общие. Облачная задача уже изолирована; дополнительный Git worktree создавать только по явной просьбе пользователя.
- Не выполнять force push, reset с потерей изменений, удаление чужих файлов или переписывание чужих коммитов.

## Разделение задач

- В начале работы назвать задачу и файлы, которые планируется менять. Это объявление области работы, а не автоматическая блокировка для другого агента.
- По умолчанию Claude занимается правилами, игровыми документами, журналом решений и публикацией артефактов; Codex — Python, HTML-шаблонами, проверками и средой разработки. Пользователь может распределить задачи иначе.
- Если оба задания требуют один исходный файл, сначала завершить и объединить одну задачу, затем обновить основу второй. Не предполагать, что второй агент видит текущий чат или незапушенные изменения.
- Исправление программы не даёт разрешения менять цены, баланс, решения мастера или скрытые сведения персонажа. Соблюдать предметные ограничения `CLAUDE.md`.

## Генерируемые документы

- Карточки, реестры, HTML, отчёты экономики и правила за столом зависят от общих исходников. Менять исходник или шаблон; генерируемые файлы вручную не редактировать.
- Проверочную генерацию делать в свежей временной копии вне checkout, без `.git`. Так она не перезапишет чужие или незавершённые документы. Это временная копия файлов, не дополнительная ветка или worktree.
- В коммит задачи включать исходники и инструкции. Если пользователю нужны готовые документы в этой же задаче, собрать и проверить их из согласованной версии исходников и явно перечислить включённые результаты.
- При объединении параллельных задач итоговые документы собирает один интегратор после объединения исходников. Конфликты в результатах генерации разрешать пересборкой, а не выбором целого файла одного агента.
- Использовать `python3 -B`, чтобы не создавать `__pycache__`. Временные `sim.json` и другие результаты держать в копии; не удалять заранее существовавшие пользовательские файлы.

## Передача и объединение

- Перед передачей проверить diff и выполнить проверки, относящиеся к изменению. Для карточек: `python3 -B scripts/cards/check.py`, ожидается 0 ошибок. Для интерфейса дополнительно проверить поведение в браузере.
- Коммитить только файлы своей задачи, перечисляя пути явно; не использовать без проверки `git add .`. Отправить свою ветку обычным push. PR не создавать, если пользователь отдельно не попросил.
- В ответе указать ветку, полный SHA коммита, изменённые файлы, выполненные проверки и зависимые документы, которые нужно пересобрать. Не объявлять изменения объединёнными до проверки общей ветки.
- Claude получает ветку или SHA от пользователя, выполняет `git fetch origin`, проверяет diff и объединяет изменения в чистом checkout общей ветки. Предпочитать `git merge --no-ff origin/codex/<задача>`: это сохраняет происхождение работы и предотвращает повторное внесение уже объединённых коммитов.
- При конфликте разобраться в обоих изменениях. Если конфликт затрагивает игровые решения или несовместимые требования, запросить решение пользователя; не подменять его механическим выбором ours/theirs.
- После объединения пересобрать затронутые документы, выполнить проверки и отправить общую ветку обычным push. Публикация артефактов — отдельный шаг, её выполняет Claude в рамках разрешённой задачи.
- Уже начатая сессия другого агента должна сначала получить сообщение о новых инструкциях, обновить Git и перечитать `AGENTS.md` и `CLAUDE.md`. Файлы инструкций сами по себе не синхронизируют активные сессии.
