# Справочник правил и сверка документов

Codex, 09.10.2026. Технический перенос по первому пакету внешнего аудита; цены, игровые решения и сценарные допущения сохранены.

**Как читать.** Для изменения справочного числа начни с `../rules.json`; для проверки документов запусти команды ниже. После интеграции пересобери помощник из исходников.

## Изменять числа в rules.json

Формат версии 1:

- `tables` — числа и параметры правил. Ключи уровней в JSON — строки; совместимый интерфейс `rules_data.py` превращает их в целые числа. Цены катализаторов хранятся по порядкам; соответствие порядков уровням хранится отдельно. Таблицы по уровням и данные для JavaScript строятся из них.
- `scenarios.player` и `scenarios.week` — отдельные исторические допущения о владении и лабораториях. Описание и источник записаны рядом с числами. Различия этих сценариев сохранены.
- `provenance` — документ и раздел, из которых перенесена таблица. Здесь не вводятся новые статусы решений: актуальный статус следует смотреть в правилах и журнале.

`rules_data.py` сохраняет прежние имена констант и типы таблиц. Это позволяет переносить потребителей поэтапно. Python-модели, сборщик карточек и помощника используют этот интерфейс. Сборщик помощника встраивает данные в автономный HTML; запросов к `rules.json` при игре нет.

Первый перенос охватывает справочник из прежнего `rules_data.py`, копии цен катализаторов в `sim_player.py` и `table_tools.js`, таблицы мастерства/лабораторий в `report.py` и `sim_volume.py`. Все числа во всех исторических отчётах автоматически не заменяются. Ручные шпаргалки остаются документами, проверяемыми скриптом.

## Задавать предмет в модели явно

Функции `potion_bonus`, `exact`, `run_catalyst`, `scenario`, `scenario_mc`, `breakeven` и модель `sim_guidance.sim` требуют именованные параметры `item_kind` и `level`.

```python
from sim import scenario
from rules_data import P_SL, HERB, P_PRICE, CAT_PRICE

level = 9
result = scenario(
    16, P_SL[level], level * HERB[level], P_PRICE[level] * .85,
    CAT_PRICE[level], .5, 2,
    item_kind='potion', level=level, allow_up_to_10=True,
)
```

`item_kind` принимает `potion`, `ink`, `elixir`, `charge`, `flask`. Бонусы зелья получают только `potion`. Поддержка остальных видов здесь обозначает отсутствие бонусов зелий, а не полную модель всех бонусов качества этих предметов. Долгая варка по-прежнему рассчитывается отдельной моделью.

`allow_up_to_10=True` сохраняет прежнее допущение 9.9 → 10.10. Значение `False` позволяет исследовать потолок результата 9.9 без изменения правил проекта. Обе модели расчёта получают один и тот же параметр. Стандартные документы используют прежнее значение.

## Проверять документы без генерации

```sh
python3 -B scripts/check_rule_documents.py
```

Сверяются выбранные действующие фрагменты:

- Ядро: СЛ, порядок катализаторов, табличная СЛ/атака применения, лестница нестабильности, объёмы долгой варки, параметры формул партий.
- Шпаргалка варки: СЛ, порядок и лестница катализаторов, лаборатории, таблицы партий зелий и эликсиров.
- Экономика для мастера: СЛ, травы, расход катализатора и цена продажи в таблице окупаемости; цены и СЛ изготовления катализаторов. Цена продажи сравнивается с учётом одного знака после запятой.

Если обязательный документ, таблица или строка отсутствует, проверка завершается ошибкой. Сообщение называет документ, параметр и значения. Проверка не сравнивает исторические бонусы персонажа с основными правилами и не трактует случайное число в альтернативе как действующий параметр.

Шпаргалки свитков и кузнеца принадлежат другим системам ремёсел. Они не включены в этот первый набор проверок. Скрипт также не доказывает согласованность всей прозы или полноту карточек.

Для временной копии и отдельного справочника доступны `--root` и `--rules`.


Путь Chromium выбирать по установленному браузеру. Общая проверка собирает результаты в новой временной копии. Если готовый помощник в checkout ещё не пересобран, она отдельно сообщает, что HTML устарел.

Валидатор сохранения использует итеративный обход, отклоняет опасные ключи и глубину больше 32. У обычного сохранения в браузерном сценарии глубина меньше 10. Отказ происходит до предложения применить сохранение; состояние и журнал остаются прежними. Ограничение размера файла 5 МБ сохранено.

## Передать изменения интегратору

В ветке задачи находятся исходники и проверки. После объединения требуется пересобрать `Помощник варки.html` через `scripts/cards/helper.py`. Проверочная сборка экономики должна воспроизводить прежние числовые таблицы. Публикация помощника остаётся отдельным шагом.
