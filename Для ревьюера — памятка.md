# Памятка для ревьюера

Актуализировано 13.11.2026. Проверяйте текущую ветку и исходники: готовые HTML и расчётные разделы собираются из них автоматически. Эта памятка задаёт порядок ревью; правила игры и статусы решений хранятся отдельно.

## Что проверить сначала

- Укажите коммит, который смотрите. Для ошибки в помощнике или пульте добавьте идентификатор «Сборка …» внизу страницы.
- Сверяйте действующее правило с журналом решений. Замечания к балансу формулируйте как предложения, сохраняя текущие числа до отдельного решения.
- Проверяйте удобство чтения: понятен ли первый экран, находится ли нужное правило, видны ли ограничения расчёта.
- Для ошибки поведения укажите шаги воспроизведения, ожидаемый и фактический результат.

**Как читать.** Ниже — где получить проект, какие файлы служат источниками и как оформить замечание. Подробные команды сборки — в [scripts/README.md](scripts/README.md).

## Где исправлять результат сборки

| Результат | Исходник и сборщик |
| --- | --- |
| Полный HTML правил, правила за столом | Полные правила → `scripts/rules_html.py`, `scripts/table_rules.py` |
| Каталог карточек и реестр | `scripts/cards/cards_data.py`, `cards_meta.py`, `src/` → сборщики в `scripts/cards/` |
| Книга игрока | `Для игрока — книга алхимии.md`, реестр документов в `scripts/player_book.py`, шаблон `scripts/player_book_tpl.html` |
| Расчётные области справки группы | `scripts/party_kit_report.py --write` и `scripts/elixir_catalog_review.py --write`; каждый обновляет свой раздел одного Markdown |
| Расчёты алхимии, заклинаний и метамагии | `scripts/bestiary_report.py --write`, `scripts/alchemy_bestiary_report.py --write`, `scripts/alchemy_magic_review.py --write`; области разделены через `scripts/magic_guide.py` |
| Недельные расчётные таблицы | `scripts/weekly_economy_report.py --write`; пояснения за пределами расчётных областей — в Markdown |
| Помощник варки | `scripts/cards/helper.py`, `helper_tpl.html` и модули в `scripts/cards/`; запасы — через подтверждённый снимок |
| Пульт мастера | `scripts/cards/master_panel.py`, `master_tpl.html`, текущие вопросы мастеру |
| Обычные HTML документов | Соответствующий Markdown → `scripts/master_html.py` |

Собранные файлы вручную не редактируются. Полные правила и правила за столом, Markdown и его HTML — связанные формы одного материала. Генерация выполняется в свежей временной копии без `.git`; в ветку переносят только результаты своей задачи.

## Какие проверки нужны

Выбирайте минимальную область по [инструкции сборки](scripts/README.md). Для текста достаточно сверки смысла и затронутой сборки. Код проверяют относящимися к нему тестами; браузерные сценарии нужны при изменении интерфейса или его поведения. Числовую модель пересчитывают при изменении её входов или алгоритма. CI выбирает область по изменённым файлам; результат отдельной проверки не равен полному прогону проекта.

Логи сессий, исходные материалы мастера и датированные снимки сохраняются. Текст и форматирование логов без отдельного запроса игрока не меняют. Старые аудиты и удалённые отчёты доступны в Git; актуальная выжимка — в [истории проверок](История проверок — оглавление.md).

## Как оформить отзыв

| Файл и место | Наблюдение | Ожидаемый результат или предложение | Важность |
| --- | --- | --- | --- |
| `Пульт мастера.html`, вопрос 19 | Шаги и фактическое поведение | Что должно произойти | ошибка / неудобство / пожелание |

Один пункт — одна проверяемая проблема. Указывайте раздел или строку исходника, условия расчёта либо шаги воспроизведения. Противоречие правил, ошибку реализации и предложение нового баланса описывайте отдельными пунктами. Повторно перечислять историю утверждений в отзыве не нужно: достаточно ссылки на соответствующее решение.
